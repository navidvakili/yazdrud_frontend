# معماری پروژه پرتال جامع دانشگاهی

## نمای کلی

پروژه **پرتال جامع دانشگاهی کارانت** یک سیستم یکپارچه مدیریت امور دانشگاهی است که با معماری **تفکیک‌شده (Decoupled)** طراحی شده است:

- **بک‌اند:** لاراول (Laravel) — ارائه APIهای REST
- **فرانت‌اند:** React + TypeScript + Vite — SPA مستقل

---

## مدیریت تب‌ها (Tab Management)

### موجودیت Tab

```typescript
interface Tab {
  id: string;
  title: string;
  iconName: string;
  moduleType?: string;
}
```

### حداکثر تب‌های همزمان

- **مقدار:** `MAX_TABS = 12` در `src/lib/constants.ts`
- **مکان اعمال:** تابع `handleOpenTab` در `App.tsx`
- **نحوه اعمال:** شرط `if (tabs.length >= MAX_TABS)` از ایجاد تب جدید جلوگیری می‌کند.

### حالت‌های UI مرتبط

| حالت | متغیر State | توضیح |
|------|-------------|-------|
| نمایش هشدار محدودیت | `showLimitAlert` | مودال تمام‌صفحه با پیغام هشدار |
| تأیید پاک‌سازی همه تب‌ها | `confirmClearActive` | مرحله دوم تأیید برای پاک‌سازی |
| تب فعال | `activeTabId` | شناسه تب جاری |
| لیست تب‌ها | `tabs: Tab[]` | آرایه تب‌های باز |

### مودال هشدار محدودیت تب

هنگام رسیدن به حداکثر ۱۲ تب، یک مودال تمام‌صفحه با امکانات زیر نمایش داده می‌شود:

1. **آیکون هشدار** — `AlertTriangle` با انیمیشن `bounce`
2. **عنوان:** "ظرفیت تب‌های مرکز کار پر شده است!"
3. **توضیحات:** اطلاع‌رسانی درباره حداکثر ۱۲ تب همزمان
4. **دکمه پاک‌سازی همه تب‌ها** — با تأیید دو مرحله‌ای (`confirmClearActive`)
5. **دکمه بازگشت** — "متوجه شدم (بازگشت)"

### نمایش تعداد تب‌ها در DashboardModule

در پیشخوان اصلی (DashboardModule)، دو کارت نمایش داده می‌شود:

- **تب همزمان مجاز:** ۱۲ (حداکثر مجاز)
- **تب فعال فعلی:** تعداد تب‌های باز شده توسط کاربر

## احراز هویت

- **پکیج بک‌اند:** Laravel Fortify
- **روش:** API Token-based (Bearer Token در هدر Authorization)
- **ذخیره‌سازی توکن:** `localStorage` با کلید `portal_token`
- **ذخیره‌سازی کاربر:** `localStorage` با کلید `portal_user`

### لاگین

1. ارسال `POST /api/login` با credentials
2. دریافت `access_token` و اطلاعات کاربر
3. ذخیره در `localStorage`
4. تغییر وضعیت به `authenticated`

### خروج

1. ارسال `POST /api/logout` (حذف توکن در سرور)
2. پاک‌سازی `localStorage`
3. بازگشت به صفحه ورود

### بازیابی نشست (Session Restore)

در بارگذاری اولیه، برنامه چک می‌کند که آیا `portal_user` و `portal_token` در `localStorage` وجود دارند. در صورت وجود، کاربر مستقیماً به حالت احراز هویت شده می‌رود.

## تم (Theme)

- **مقادیر:** `'light' | 'dark'`
- **ذخیره‌سازی:** `localStorage` با کلید `portal_theme`
- **اعمال:** کلاس `dark` روی `<html>` برای Tailwind
- **دکنه تغییر:** کامپوننت `ThemeToggle` در نوار بالایی (Header)

## API Service

### ساختار فعلی

```typescript
class ApiService {
  // استفاده از توابع API در lib/functions.ts
  async login(credentials): Promise<AuthResponse>
  async logout(): Promise<void>

  async updateProfile(data): Promise<User>
  async changePassword(current, new): Promise<{message}>
  async getNavigation(): Promise<NavItem[]>
  async getUserRoles(): Promise<{primary_role, all_roles}>
  async getUserPermissions(): Promise<PermissionItem[]>
  async switchRole(role): Promise<User>
  getStoredUser(): User | null
  getStoredToken(): string | null
  isAuthenticated(): boolean
}
```

### توابع API در lib/functions.ts

| تابع | توضیح |
|------|-------|
| `API(URL, params, method)` | درخواست عمومی API |
| `APISendFiles(URL, formData)` | آپلود فایل با multipart/form-data |
| `downloadFile(URL, filename)` | دانلود فایل |
| `getFileViewUrl(URL)` | دریافت URL برای نمایش فایل |

## تغییر نقش (Role Switching)

کاربران می‌توانند بین نقش‌های خود جابجا شوند:

1. ارسال `PUT /api/user/switch-role` با نقش جدید
2. به‌روزرسانی اطلاعات کاربر
3. پاک‌سازی همه تب‌ها (برای نمایش منوهای نقش جدید)
4. دریافت مجدد منوهای ناوبری

## ماژول‌های قدیمی (Legacy Modules)

ماژول‌هایی که هنوز به React منتقل نشده‌اند، از طریق `<iframe>` در `LegacyModules.tsx` نمایش داده می‌شوند. آدرس این iframe‌ها از طریق API ناوبری دریافت می‌شود.

## ماژول دوره‌های آموزشی (Course Module)

### معماری کلی

ماژول دوره‌های آموزشی از دو بخش اصلی تشکیل شده است:

1. **بک‌اند (Laravel):** مدل‌ها و کنترلر API برای مدیریت دوره‌ها و ثبت‌نام‌ها
2. **فرانت‌اند (React):** کامپوننت `CourseCoursework.tsx` با قابلیت‌های نمایش، جستجو، ایجاد، ویرایش و مدیریت ثبت‌نام

### مدل‌های بک‌اند

#### Course (دوره آموزشی)

- **فایل:** `portal_backend/app/Models/Course.php`
- **جدول:** `courses` (دیتابیس موجود — بدون تغییر)
- **فیلدهای اصلی:** `title`, `amount`, `active`, `image`, `description`, `syllabus`, `duration`, `instructor`, `start_date`, `end_date`, `capacity`, `registered_count`
- **Accessorها:**
  - `getImageUrlAttribute()` — بازگرداندن آدرس کامل تصویر یا تصویر پیش‌فرض
  - `getIsAvailableAttribute()` — بررسی ظرفیت خالی و فعال بودن
  - `getRemainingCapacityAttribute()` — محاسبه ظرفیت باقی‌مانده
- **Relationshipها:**
  - `registrations()` — ثبت‌نام‌های پرداخت شده (از طریق `registertuts`, `registertuts_payments`, `gateway_transactions`)
  - `certificates()` — گواهی‌نامه‌های مرتبط

#### Registertut (ثبت‌نام دوره)

- **فایل:** `portal_backend/app/Models/Registertut.php`
- **جدول:** `registertuts`
- **فیلدهای کلیدی:** `kodmeli`, `course_id`, `type`, `fullname`, `id_edu`, `mobile`, `email`, `payment_method`, `bank_receipt`, `verified_receipt`, `rejected_receipt`, `rejection_reason`, `certificate_approved`
- **متدهای وضعیت:**
  - `getActualStatusAttribute()` — تعیین وضعیت واقعی بر اساس روش پرداخت (آنلاین: بررسی تراکنش، بانکی: بررسی فیش)
  - `getActualStatusTextAttribute()` — متن فارسی وضعیت
  - `getCertificateStatusTextAttribute()` — وضعیت گواهی‌نامه

#### RegistertutsPayment (پرداخت ثبت‌نام)

- **فایل:** `portal_backend/app/Models/RegistertutsPayment.php`
- **جدول:** `registertuts_payments`
- **نقش:** جدول واسط بین `registertuts` و `gateway_transactions`

#### GatewayTransaction (تراکنش درگاه)

- **فایل:** `portal_backend/app/Models/GatewayTransaction.php`
- **جدول:** `gateway_transactions`
- **فیلدهای کلیدی:** `username`, `type`, `status`, `port`, `price`, `ref_id`, `tracking_code`

### کنترلر API

- **فایل:** `portal_backend/app/Http/Controllers/Api/CourseController.php`
- **متدها:**

| متد | مسیر | توضیح |
|------|------|-------|
| `index` | `GET /api/courses` | لیست دوره‌ها با فیلتر (search, active, page, per_page) |
| `show` | `GET /api/courses/{id}` | جزئیات یک دوره |
| `store` | `POST /api/courses` | ایجاد دوره جدید (با آپلود تصویر) |
| `update` | `PUT /api/courses/{id}` | به‌روزرسانی دوره |
| `destroy` | `DELETE /api/courses/{id}` | حذف دوره (در صورت وجود ثبت‌نام مسدود است) |
| `registrations` | `GET /api/courses/{id}/registrations` | لیست ثبت‌نام‌های یک دوره |
| `approveReceipt` | `POST /api/courses/registrations/{id}/approve` | تأیید فیش بانکی |
| `rejectReceipt` | `POST /api/courses/registrations/{id}/reject` | رد فیش بانکی (با دلیل) |
| `statistics` | `GET /api/courses/statistics` | آمار دوره‌ها (تعداد کل، فعال، ثبت‌نام‌ها، فیش‌های در انتظار) |

### کامپوننت CourseCoursework

- **فایل:** `src/components/CourseCoursework.tsx`
- **وضعیت‌های نمایش (ViewMode):** `'list' | 'add' | 'registrations' | 'stats'`
- **قابلیت‌ها:**

| بخش | توضیح |
|------|-------|
| **نمایش لیست دوره‌ها** | کارت‌های گرید با تصویر، وضعیت فعال/غیرفعال، مدرس، شهریه، ظرفیت، تاریخ شروع |
| **جستجو** | فیلتر بر اساس عنوان یا نام استاد |
| **ایجاد دوره جدید** | فرم گسترش‌یافته با تمام فیلدها |
| **ویرایش دوره** | مودال ویرایش با تمام فیلدها |
| **حذف دوره** | با تأیید کاربر (در صورت وجود ثبت‌نام مسدود می‌شود) |
| **فعال/غیرفعال کردن** | تغییر وضعیت با یک کلیک |
| **مدیریت ثبت‌نام‌ها** | جدول ثبت‌نام‌ها با فیلتر وضعیت (همه/در انتظار/تایید شده/پرداخت شده/رد شده) |
| **تأیید/رد فیش بانکی** | دکمه‌های عملیات به همراه مودال رد با دلیل |
| **آمار** | نمایش کارت‌های آماری (کل دوره‌ها، فعال، ثبت‌نام‌ها، فیش‌های در انتظار) و پرمخاطب‌ترین دوره‌ها |

- **هشدارها:** پیام‌های موفقیت/خطا با انیمیشن (AnimatePresence)
- **فرمت‌دهی:** اعداد به فرمت فارسی (ریال) با `toLocaleString('fa-IR')`
